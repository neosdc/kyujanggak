START / 설치와 인증

설치하고, 모델을 연결하고, 작업을 요청합니다.

  1. Windows 환경을 준비합니다.

    필수 npm 방식은 Node.js 22.19 이상이 필요합니다. 네이티브 Windows의 기본 Bash 명령 실행에는 Git for Windows를 준비하세요. 터미널은 Windows Terminal을 권장합니다.

  2. 공식 npm 패키지를 설치합니다.

    npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version

    일반 npm 설치에는 의존성의 lifecycle script가 필요하지 않습니다. npm 방식은 전이 의존성을 고정하지 않습니다.

    공식 설치 스크립트 방식도 있습니다.

    공식 설치 프로그램은 의존성을 고정하고, 필요하면 Node.js를 설치할 수 있습니다. 이 경로로 설치한 Pi는 pi update로 업데이트합니다. 아래 코드는 안내용이며 이 문서가 실행하지 않습니다.

    powershell -c "irm https://pi.dev/install.ps1 | iex"

    macOS / Linux: curl -fsSL https://pi.dev/install.sh | sh. 두 설치 방식 중 하나를 선택하세요.

  3. 작업 폴더에서 Pi를 시작합니다.

    cd C:\path\to\your-project
pi

    이 폴더를 기준으로 관련 파일, 프로젝트 지침과 설정을 찾고 저장된 세션을 분류합니다.

  4. 인증하고 모델을 선택합니다.

    /login
/model

    /login에서 제공자를 선택하고 구독 연결 또는 API 키 등록 절차를 따릅니다. /model로 사용 가능한 모델을 고릅니다.

    참고Pi 자체가 AI 모델은 아닙니다.

    지원 제공자의 구독, API 또는 로컬 모델에 접근할 수 있어야 합니다. 인증 지원과 이용 요금은 제공자별로 다릅니다.

LOOP / 작업 과정

읽기 → 수정 → 실행 → 검토를 이어갑니다.

작업 중 방향을 바꾸려면

  • Enter: 현재 응답과 도구 호출이 끝난 뒤 반영할 지시를 보냅니다.
  • Alt+Enter: 현재 작업이 끝난 다음 수행할 요청을 대기시킵니다.
  • Escape: 현재 작업을 중단합니다.

나중에 이어서 하려면

세션 저장을 끄지 않았다면 자동으로 저장됩니다. 같은 작업 폴더에서 다음을 실행합니다.

pi --continue

다른 저장된 세션은 /resume에서 선택합니다.

REFERENCE / 명령과 입력

필요한 기능은 입력창에서 바로 찾습니다.

/를 입력해 사용 가능한 명령을 검색하세요. 스킬·템플릿·확장 기능이 명령을 추가할 수 있습니다.

명령 / 입력하는 일알아둘 점
@파일 검색 후 요청에 추가경로는 Tab으로 완성할 수 있습니다.
/login, /logout모델 제공자 인증 관리지원되는 구독 또는 API 키를 연결합니다.
/model사용 모델 선택Ctrl+L로도 선택창을 엽니다.
/thinking모델의 추론 수준 선택모델이 지원하는 수준에서 선택합니다.
/settings일반 설정 변경터미널 표시 방식 등 환경을 조정합니다.
/new새 세션 시작새로운 주제로 전환할 때 사용합니다.
/resume저장된 세션 선택최근 세션은 CLI의 pi --continue로 이어갑니다.
/name, /session세션 이름 지정 / 상태 확인ID, 메시지 수, 토큰 사용량, 비용 등을 확인합니다.
/tree, /fork, /clone대화에서 다른 접근으로 분기기존 대화를 보존하면서 다른 방향을 시도합니다.
/compact모델에 전달하는 대화 기록 압축긴 대화의 문맥을 정리합니다.
!git status셸 실행 후 출력을 모델에 전달네이티브 Windows에서도 기본적으로 Bash를 사용합니다.
!!명령출력을 모델에 보내지 않고 셸 실행실행 권한 자체를 제한하는 기능은 아닙니다.
/copy, /export마지막 답변 복사 / 세션 내보내기내보내기는 HTML 또는 JSONL을 지원합니다.
/share세션 업로드 후 공유 링크 생성외부 전송 전 프롬프트·파일 내용·도구 출력·인증정보 노출을 확인하세요.
/hotkeys현재 단축키 확인Windows Terminal에서 일부 키 설정이 필요할 수 있습니다.
Escape, Ctrl+O작업 중단 / 도구 출력 펼치기·접기긴 프롬프트는 Ctrl+G로 외부 편집기에서 작성할 수 있습니다.

CUSTOMIZE / 지침과 확장

필요한 만큼만 기능을 더합니다.

프로젝트 지침 예시: AGENTS.md
# 개발 지침

- 기존 코드의 스타일을 따른다.
- 새 의존성은 꼭 필요한 경우에만 추가한다.
- 코드 변경 후 관련 테스트와 빌드를 실행한다.
- 완료 시 변경 내용과 검증 결과를 설명한다.

지침 파일은 모델의 행동을 유도합니다. 운영체제 권한을 제한하거나 준수를 보장하는 기능은 아닙니다.

자동화에 연결할 때

대화형 터미널 외에 print·JSON 모드, RPC, TypeScript SDK를 지원합니다. 다른 앱이나 작업 흐름에 Pi를 통합할 때 사용합니다.

잘 맞는 사용 방식

  • 터미널과 Git으로 변경을 검토하는 개발
  • 작업에 따라 모델과 제공자를 선택하는 환경
  • 반복 절차와 사용자 도구를 구성하는 작업

WINDOWS / 셸 선택

Pi를 여는 터미널과 도구가 쓰는 셸을 구분합니다.

선택 설정: 모델의 Bash 도구를 PowerShell로 바꾸기

공식 설정 파일 ~/.pi/agent/settings.json에 다음 값을 기존 설정과 병합한 뒤 Pi를 다시 시작합니다. 아래 전체 예시로 기존 파일을 덮어쓰지 마세요.

{
  "defaultTools": ["read", "powershell", "edit", "write"]
}

!와 !! 입력 명령은 계속 Bash를 사용합니다. PowerShell 도구는 네이티브 Windows에서만 사용할 수 있습니다.

공식 Windows 문서는 Windows Terminal을 권장합니다. 일부 콘솔 호스트와 구버전 터미널에는 표시·단축키 문제가 있어 설치 환경별 안내를 확인하세요.

PERMISSIONS / 실행 전 알아둘 점

작업 폴더는 권한을 가두는 경계가 아닙니다.

가장 중요Pi는 도구 호출마다 승인을 받지 않습니다.

Pi와 확장 기능은 실행한 사용자 계정의 권한으로 파일을 읽고, 수정하고, 명령을 실행합니다. 프로젝트 폴더에서 시작해도 그 밖의 접근 가능한 경로에 영향을 줄 수 있습니다.

변경을 복구하고 검토하기

  • 중요한 변경 전 Git 상태와 백업을 확인합니다.
  • 작업 후 diff와 테스트·빌드 결과를 검토합니다.
  • 신뢰하기 어렵거나 무인으로 수행할 작업에는 필요한 자원만 제공한 격리 환경을 사용합니다.

신뢰와 공유를 구분하기

  • 프로젝트 신뢰는 로컬 설정·확장 등의 로딩을 제어합니다. 실행 권한을 격리하지 않습니다.
  • 확장 기능은 실행 가능한 코드이므로 출처와 동작을 확인합니다.
  • /share는 실제 업로드입니다. 세션에 파일 내용이나 인증정보가 포함될 수 있습니다.
