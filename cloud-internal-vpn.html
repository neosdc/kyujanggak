구조패킷 경로구성 순서설정 예시보안·운영검증

클라우드 VM ↔ 내부망 게이트웨이 · WireGuard 예시

VPN은 두 네트워크 사이에
암호화된 IP 경로를 만든다

외부 사용자는 도메인으로 클라우드 Nginx에 접속한다. Nginx는 VPN 경로로 내부 웹 서버에 접속한다.

예시: service.example.com · 클라우드 172.27.10.1 · 내부 게이트웨이 172.27.10.2 · 웹 서버 10.0.0.20:8080

역방향 터널과의 차이 SSH -R은 지정한 VM 포트 하나를 내부 서비스 하나로 전달한다. VPN은 IP 경로를 만든다. 따라서 여러 서비스로 확장하기 쉽지만, 라우팅과 방화벽 범위를 더 엄격히 관리해야 한다.

라우팅

요청 경로와 응답 경로가 모두 있어야 동작한다

내부 게이트웨이가 웹 서버와 다른 장비라면 IP 포워딩과 반환 경로가 필요하다. 반환 경로 대신 게이트웨이에서 SNAT을 쓰면 설정은 단순해지지만 웹 서버에서 원래 VPN 출발지 IP가 보이지 않는다. 이 예시의 실제 외부 사용자 IP는 Nginx가 전달하는 신뢰된 헤더로 처리한다.

구성 순서

주소 범위와 통신 조건을 먼저 정한다

1

연결 조건 확인

내부 게이트웨이에서 VM의 UDP 51820으로 아웃바운드 통신이 가능한지 확인한다. 클라우드와 내부망의 IP 범위가 겹치지 않아야 한다.

2

VM과 DNS 준비

고정 공개 IP를 가진 VM을 만든다. 보안 그룹에서 TCP 443과 VPN용 UDP 51820을 허용한다. SSH 관리 포트는 가능한 출발지로 제한한다.

3

VPN 키와 주소 지정

각 장비의 개인키·공개키를 만들고 VPN 주소를 172.27.10.1/30, 172.27.10.2/30으로 지정한다. 개인키는 장비 밖으로 공개하지 않는다.

4

피어·경로 설정

VM은 10.0.0.20/32로 가는 경로를 내부 피어에 지정한다. 내부 게이트웨이는 VM의 VPN 주소로 돌아가는 경로와 포워딩을 설정한다.

5

방화벽 범위 제한

VPN 전체를 신뢰하지 말고 VM의 VPN 주소에서 10.0.0.20:8080으로 가는 TCP만 허용한다. 다른 내부 대역 접근은 막는다.

6

Nginx·인증서·DNS

Nginx가 10.0.0.20:8080으로 프록시하도록 설정한다. TLS 인증서를 발급·자동 갱신하고 도메인의 A 레코드를 VM 공개 IP로 연결한다.

내부망이 NAT 뒤에 있는 경우 내부 게이트웨이가 VM 공개 IP로 먼저 UDP 패킷을 보낸다. WireGuard의 PersistentKeepalive는 NAT 매핑을 유지하는 데 도움을 준다. 내부망의 UDP 아웃바운드가 차단되면 이 예시 구성은 동작하지 않는다.

핵심 설정 예시

VPN 경로는 좁게, 웹 공개는 Nginx에서 처리한다

아래는 설계 확인용 예시다. 실제 키, 인터페이스 이름, 운영체제별 포워딩·방화벽 명령은 환경에 맞춰 적용한다.

클라우드 VM의 WireGuard 피어

[Interface]
Address = 172.27.10.1/30
ListenPort = 51820
PrivateKey = <VM 개인키>

[Peer]
PublicKey = <내부 게이트웨이 공개키>
AllowedIPs = 172.27.10.2/32, 10.0.0.20/32

내부 게이트웨이의 WireGuard 피어

[Interface]
Address = 172.27.10.2/30
PrivateKey = <내부 게이트웨이 개인키>

[Peer]
PublicKey = <VM 공개키>
Endpoint = 203.0.113.10:51820
AllowedIPs = 172.27.10.1/32
PersistentKeepalive = 25

VM의 Nginx 전달 대상

location / {
    proxy_pass http://10.0.0.20:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Forwarded-For $remote_addr;
}
중요 AllowedIPs만으로 내부 웹 접근 정책이 완성되지 않는다. 내부 게이트웨이 방화벽에서 172.27.10.1 → 10.0.0.20:8080/TCP만 허용해야 한다. 웹 서버가 응답을 VM으로 돌려보낼 경로도 필요하다.

VPN은 연결 범위가 넓어질 수 있어 경계 설정이 중요하다

클라우드의 관리형 사이트 간 VPN도 선택할 수 있다. 다만 제품에 따라 내부망 쪽 고정 공개 IP, 호환되는 VPN 장비, IKE/IPsec 포트, NAT-T 또는 BGP 설정이 필요하다. 내부망의 아웃바운드 조건과 클라우드 제품 요구사항을 먼저 대조해야 한다.
