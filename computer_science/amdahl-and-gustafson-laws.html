병렬 처리 · 성능 모델

같은 일을 더 빨리 끝낼까,
같은 시간에 더 많이 할까?

암달의 법칙과 구스타프손의 법칙은 병렬 처리의 효과를 서로 다른 작업 조건에서 계산한다. 차이는 무엇을 고정하는가에 있다.

핵심 직관

한 사람이 해야 하는 일은 코어를 늘려도 남는다

암달의 질문

오늘 주문받은 빵 100개를 가장 빨리 끝내려면 오븐을 몇 대까지 늘릴 가치가 있을까?

구스타프손의 질문

오늘도 100분 동안 굽는다면 오븐을 늘려 빵을 몇 개까지 만들 수 있을까?

이 비유에서 준비·검수는 순차 부분이고, 굽기는 병렬 부분이다. 실제 프로그램에서는 굽기에 해당하는 작업도 데이터 분할, 통신, 동기화 때문에 완벽하게 나뉘지 않을 수 있다.

법칙 1 · 고정된 작업

암달의 법칙: 순차 부분이 시간 단축의 상한을 정한다

암달의 법칙은 같은 크기의 작업을 처리할 때 코어 수를 늘려 얻을 수 있는 속도 향상을 계산한다. 코어 1개에서 걸리는 시간을 기준으로, 순차 부분의 비율을 s, 병렬화할 수 있는 부분의 비율을 p라고 둔다. 따라서 s + p = 1이다.

SA(N) = T1 / TN = 1 / (s + p/N) = 1 / ((1−p) + p/N)
T1코어 1개로 처리한 원래 작업의 시간
TN같은 작업을 N개 코어로 처리한 시간
p와 s코어 1개 실행 시간을 기준으로 한 비율

식을 유도하면

원래 실행 시간을 1로 정규화한다. 순차 부분은 s, 병렬 부분은 p다. 병렬 부분이 N개 코어에 균등하게 분배되면 그 시간은 p/N이 된다.

TN = s + p/N

속도 향상은 원래 시간 1을 새 시간으로 나눈 값이다.

SA(N) = 1 / (s + p/N)

수치 예시. s = 0.1, p = 0.9, N = 10이면 새 시간은 원래 시간의 0.1 + 0.9/10 = 0.19다. 따라서 속도 향상은 1/0.19 ≈ 5.26배다.

상한. N이 무한히 커지면 p/N은 0에 가까워진다. s > 0이면 최대 속도 향상은 1/s = 1/(1−p)다. s = 0인 이상적인 경우에만 이 상한이 사라진다.

경계값. N = 1이면 속도 향상은 1배다. 병렬화할 수 있는 부분이 전혀 없으면 p = 0이고 역시 1배다. 모든 작업을 완벽하게 병렬화할 수 있는 이상적인 p = 1에서는 N배다.

어떻게 해석해야 하나

병렬화 비율이 90%라는 말은 코어 1개로 실행했을 때 시간의 90%를 차지한 부분을 나눌 수 있다는 뜻이다. 코어 10개를 쓰면 병렬 부분은 90분에서 9분으로 줄지만 순차 10분은 그대로다. 코어를 추가할수록 새로 절약하는 시간은 작아진다.

여기서 p는 병렬화할 수 있는 코드의 줄 수가 아니라 기준 실행 시간의 비율이다. 프로그램의 코드 대부분이 병렬이라도, 실제 실행 시간 대부분을 차지하는 순차 구간이 있다면 속도 향상은 작다. 반대로 실행 시간의 대부분을 쓰는 계산 구간을 병렬화하면 효과가 크다.1

암달의 법칙은 병렬 처리 밖의 최적화에도 적용된다

프로그램 시간 중 비율 f를 차지하는 부분을 k배 빠르게 만든다면 전체 속도 향상은 1/((1−f)+f/k)다. 병렬 처리에서는 개선 배수 k를 코어 수 N으로 놓은 형태가 암달의 식이다. 예를 들어 시간의 20%를 차지하는 함수만 10배 빠르게 만들어도 전체 프로그램은 1/(0.8+0.2/10) ≈ 1.22배 빨라진다.2

법칙 2 · 확장된 작업

구스타프손의 법칙: 같은 시간에 처리할 작업량을 키운다

구스타프손의 법칙은 코어가 늘었을 때 병렬 작업의 크기도 함께 키우는 상황을 설명한다. N개 코어에서 실제로 실행한 확장된 작업의 총시간을 1로 정규화하고, 그중 순차 부분의 비율을 α라고 둔다. 병렬 부분의 시간 비율은 1−α다.

SG(N) = α + N(1−α) = N − α(N−1)
αN개 코어에서 확장된 작업을 실행한 시간 중 순차 비율
1−α같은 실행에서 병렬 부분이 차지한 시간 비율
SG(N)확장된 동일 작업을 한 코어로 처리한 시간 ÷ N코어 시간

식을 유도하면

N개 코어에서 순차 작업은 α만큼, 병렬 작업은 1−α만큼 걸린다. 확장된 동일 작업을 코어 1개로 처리하면 병렬 부분에 N배의 시간이 든다.

TN = α + (1−α) = 1

T1 = α + N(1−α)

따라서 같은 확장된 작업의 속도 향상은 T1/TN이다.

SG(N) = α + N(1−α)

수치 예시. N = 10, α = 0.1이면 SG = 10 − 0.1×9 = 9.1배다. 이는 10개 코어가 100분에 끝낸 확장된 작업을 한 코어로 하면 910분 걸린다는 뜻이다.

적용 상황. 더 큰 데이터셋, 더 높은 해상도, 더 촘촘한 시뮬레이션처럼 작업 크기를 늘릴 가치가 있을 때 유용하다. 순차 시간이 거의 일정하고 병렬 작업을 충분히 늘릴 수 있어야 한다.

경계값. N = 1이면 속도 향상은 1배다. α = 1이면 확장할 병렬 작업이 없어 1배다. α = 0인 이상적인 경우에는 N배다.

‘9.1배’가 뜻하지 않는 것

원래 100분짜리 같은 작업이 10개 코어에서 100/9.1분 만에 끝난다는 뜻이 아니다. 10개 코어가 100분 동안 훨씬 큰 작업을 처리했고, 그 큰 작업을 한 코어로 수행했을 때의 시간과 비교한 값이다.

이 계산에서는 코어가 늘어도 순차 부분은 10분으로 유지되고, 나머지 90분을 채울 만큼 병렬 작업을 추가한다. 따라서 α = 0.1은 모든 크기의 작업에 자동으로 적용되는 상수가 아니다. 실제 작업이 커지면서 파일 읽기, 결과 합치기, 통신 시간도 커진다면 α는 다시 측정해야 한다.

이미지 처리로 바꾸어 보면

작업 준비에 10분이 들고 이미지 100장을 한 코어로 처리하는 데 90분이 든다고 하자. 같은 100장을 10개 코어에 나누면 암달의 계산에서는 19분이 걸린다. 구스타프손의 실험에서는 10개 코어가 각각 100장씩 처리해 이미지 1,000장을 100분에 끝낸다. 그 1,000장을 한 코어로 처리하면 10분 + 900분 = 910분이다. 이 예시는 준비 시간이 이미지 수와 무관하고 이미지별 처리 시간이 일정하다는 가정을 쓴다.3

하나의 기준 · 두 가지 실험

100분짜리 기준 작업에서 바꾸는 것은 하나뿐이다

암달은 “기존 주문 100개를 언제 끝내나?”를, 구스타프손은 “같은 근무시간에 주문을 얼마나 더 처리하나?”를 묻는다. 어느 질문이 필요한지는 성능 목표에 따라 결정된다.

수학적 관계

같은 작업으로 맞추면 두 식은 같은 답을 낸다

암달 예시의 고정 작업을 10개 코어로 처리하면 총 19분이다. 그중 순차 실행은 10분이다. 따라서 10코어 실행에서 관측한 순차 비율은 10/19 ≈ 0.5263이다. 이것이 구스타프손 식에 넣을 α다.

αN = s / (s + p/N)

위 식은 코어 1개 기준의 순차 비율 s를 N개 코어 실행에서 관측한 비율 αN로 바꾼다. 이를 구스타프손 식에 대입하면 암달의 식 1/(s+p/N)이 나온다.

흔한 오류. 암달의 s = 0.1과 구스타프손의 α = 0.1을 같은 작업의 동일한 관측값이라고 놓고 5.26배와 9.1배를 직접 비교하는 것이다. 비율을 측정한 실행과 작업 크기부터 확인해야 한다.

결과를 읽는 방법

속도 향상률, 코어 효율, 처리량은 서로 다른 값이다

속도 향상률 S(N)은 동일한 작업의 한 코어 실행 시간 T1을 N개 코어의 실행 시간 TN으로 나눈 값이다. 코어 효율 E(N)은 속도 향상률을 코어 수로 다시 나눈 값이다. E(N) = S(N)/N이며, 이상적인 선형 속도 향상 S(N)=N에서는 효율이 100%다.

지표정의10코어·고정 작업10코어·확장 작업
실행 시간작업 시작부터 끝까지19분100분
한 코어 환산 작업량해당 작업을 한 코어로 처리할 시간100분910분
속도 향상률각 실험의 한 코어 시간 ÷ 10코어 시간5.26배9.1배
코어 효율속도 향상률 ÷ 1052.6%91%

표의 두 효율은 서로 다른 크기의 작업에서 측정한 값이다. 확장 작업의 91%를 고정 작업보다 하드웨어 사용률이 높다는 직접적인 증거로 읽으면 안 된다. CPU 사용률은 코어가 바쁘게 동작한 시간의 비율이며, 코어 효율은 이상적인 선형 속도 향상에 대한 비율이다. 둘은 정의가 다르다.4

처리량은 일정 시간에 완료한 작업 수로 측정한다. 예를 들어 초당 처리한 요청 수나 분당 처리한 이미지 수다. 지연 시간은 작업 하나가 완료될 때까지 기다린 시간이다. 서버에서는 처리량을 높여도 개별 요청의 지연 시간이 줄지 않을 수 있으므로 둘을 따로 기록해야 한다.

병렬 성능 실험의 설계

강한 확장은 작업을 고정하고, 약한 확장은 코어당 일을 고정한다

고정된 입력 크기

같은 데이터셋을 두고 코어 수만 늘린다. 성능 목표는 완료 시간 단축이다. 많은 코어를 추가한 뒤에도 입력 데이터가 작으면 코어마다 맡을 일이 너무 적어져 분배 비용이 두드러진다.

커지는 입력 크기

데이터 크기나 해상도를 늘린다. 성능 목표는 정해진 시간에 더 많은 결과를 얻는 것이다. 하지만 입력이 커지면 메모리 사용량, 데이터 이동량, 결과 합치기 시간도 같이 늘어날 수 있다.

“약한 확장”을 평가할 때는 코어당 데이터량, 총 실행 시간, 메모리 용량이 함께 어떻게 변했는지 확인한다. “강한 확장”을 평가할 때는 동일한 입력과 출력 조건인지 확인한다.

직접 계산

순차 비율과 코어 수를 바꾸어 차이를 확인한다

아래 모형은 두 실험의 기준 시간을 각각 100분으로 둔다. 암달 실험에서는 기존 작업량을 유지한다. 구스타프손 실험에서는 실행 시간 100분을 유지하며 병렬 작업량을 늘린다. 각 실험에서 순차 부분의 절대 시간은 같은 값으로 설정한다.

모델의 경계

실제 성능은 분할 비용과 공유 자원의 영향을 받는다

작업 분배·동기화

스레드 시작, 결과 합치기, 잠금 대기, 노드 간 통신이 시간을 쓴다. 암달의 단순식에는 이 비용이 없다.

메모리·입출력

코어가 많아도 메모리 대역폭, 저장장치, 네트워크가 함께 늘지 않으면 병렬 부분이 1/N로 줄지 않는다.

확장 가능한 작업량

구스타프손의 계산은 유익한 병렬 작업을 늘릴 수 있어야 한다. 데이터가 작거나 순차 단계도 커지면 성립 범위가 좁아진다.

TN = s + p/N + h(N)

여기서 h(N)은 코어가 늘면서 생기는 추가 비용을 나타내는 단순화된 항이다. 이 비용이 커지면 코어를 더해도 속도 향상이 작아지거나 실행 시간이 오히려 늘 수 있다.

순차 시간은 고정된 물리량이 아니다

프로그램을 병렬화할 때 순차 구간의 길이가 바뀔 수 있다. 예를 들어 스레드 생성과 결과 합치기가 새로 생긴다. 입력을 키우면 순차적으로 읽어야 하는 데이터나 검증해야 하는 결과도 늘 수 있다. 따라서 한 번 측정한 s나 α를 모든 코어 수와 입력 크기에 그대로 적용하지 않는다.

작업을 나누는 방법도 중요하다. 한 코어가 다른 코어보다 오래 일하면 나머지는 기다린다. 이를 부하 불균형이라고 한다. 공유 메모리의 대역폭이 포화되거나 저장장치가 병목이 되면 병렬 부분 자체가 p/N보다 오래 걸린다.5

실제 시스템의 코어 증설 결정두 관점 모두통신·동기화·메모리 병목과 측정값

기억할 문장

암달은 고정된 일을 더 빨리 끝내려 할 때 남는 순차 시간이 한계를 만든다고 말한다. 구스타프손은 병렬로 할 일을 늘릴 수 있다면 같은 시간에 훨씬 큰 문제를 다룰 수 있다고 말한다. 두 법칙 모두 어떤 작업을 비교하는지와 순차 비율을 어디서 측정했는지를 명시해야 올바르게 사용할 수 있다.

실제로 계산할 때

작업 조건을 적고 시간을 재야 법칙을 적용할 수 있다

  1. 성능 목표를 정한다. 같은 입력의 완료 시간을 줄일지, 정해진 시간 안에 처리할 입력을 늘릴지 먼저 결정한다.
  2. 입력과 출력을 고정하거나 기록한다. 데이터 크기, 해상도, 처리할 항목 수, 결과의 정확도가 달라지면 비교 기준도 달라진다.
  3. 기준 실행을 측정한다. 한 코어의 총시간과 시간이 많이 드는 구간을 여러 번 재고, 편차도 함께 본다. 순차 비율은 추측보다 측정값을 우선한다.
  4. 코어별 실행을 측정한다. 2, 4, 8, 16개처럼 여러 지점에서 전체 시간, 순차 시간, 통신·동기화 대기 시간을 기록한다.
  5. 모델과 측정값을 비교한다. 실제 시간이 s+p/N보다 길다면 추가 비용과 공유 자원 병목을 조사한다. 확장 작업에서는 입력이 늘어도 순차 시간과 총시간이 유지되는지 확인한다.

측정 예. 100분짜리 한 코어 실행에서 순차 구간이 10분이라면 암달의 이상적인 10코어 예상 시간은 19분이다. 실제 10코어 실행이 27분이라면 차이 8분을 분배·대기·메모리·입출력 비용 중 어디서 썼는지 조사한다. 이 경우 실제 속도 향상은 100/27 ≈ 3.70배다.

속도 향상이 코어 수보다 커지는 “초선형 속도 향상”이 관측되기도 한다. 캐시 적중률이나 메모리 동작이 달라졌을 수 있으므로, 단순한 두 법칙만으로 원인을 결론 내리지 말고 메모리와 I/O 측정값을 함께 살펴본다.

각주 · 더 보기

다음 개념을 찾아보면 성능 분석이 더 정확해진다

아래 항목은 본문의 가정이 깨지는 지점을 이해할 때 유용하다. 제목을 열면 핵심 질문과 찾아볼 용어가 나온다.

1. 프로파일링: 병렬화할 시간을 어떻게 찾는가?

함수별 실행 시간뿐 아니라 호출 빈도, 대기 시간, 입력 크기별 변화를 측정한다. 순차 비율 s는 코드의 줄 수가 아니라 기준 실행 시간에서 차지하는 비율이다. 찾아볼 용어: CPU profiler, sampling profiler, flame graph, critical path.

2. 부분 최적화의 일반식: 어디를 먼저 빠르게 만들까?

전체 실행 시간의 비율 f를 차지하는 부분을 k배 가속하면 전체 속도 향상은 다음과 같다. 현재 시간을 많이 쓰는 부분을 고르는 데 쓴다.

S = 1 / ((1−f) + f/k)

찾아볼 용어: Amdahl’s law for optimization, performance profiling.

3. 강한 확장과 약한 확장: 작업량을 어떻게 바꾸는가?

강한 확장에서는 총 입력 크기를 고정한다. 약한 확장에서는 코어당 입력 크기를 고정한다. 구스타프손의 법칙은 확장된 작업을 일정한 실행 시간 관점에서 평가한다. 찾아볼 용어: strong scaling, weak scaling, scaled speedup.

4. 코어 효율과 CPU 사용률: 왜 서로 다른가?

코어 효율은 속도 향상률/코어 수다. CPU 사용률은 코어가 실행 중이었던 시간의 비율이다. 모든 코어가 바빠도 대기·중복 계산 때문에 코어 효율이 낮을 수 있다. 찾아볼 용어: parallel efficiency, utilization, throughput, latency.

5. 메모리 병목: 계산을 나눠도 왜 빨라지지 않는가?

모든 코어가 같은 메모리와 저장장치를 사용한다. 데이터 이동이 계산보다 오래 걸리면 코어를 추가해도 속도 향상이 작다. 계산량과 메모리 이동량의 비율을 살펴보는 Roofline 모델이 다음 단계다. 찾아볼 용어: memory bandwidth, cache locality, arithmetic intensity, Roofline model.

6. 불균형과 통신: 가장 늦은 코어를 왜 기다리는가?

병렬 구간의 완료 시간은 평균 코어 시간보다 가장 늦게 끝난 코어의 시간에 가까울 수 있다. 코어 사이의 데이터 전달과 동기화도 추가된다. 찾아볼 용어: load balancing, synchronization overhead, communication cost, critical path.

7. 유효 순차 비율: 측정값에서 병렬화의 한계를 어떻게 추정하는가?

N > 1일 때 실제로 측정한 속도 향상 S(N)에서 암달의 단순 모델에 대응하는 순차 비율을 역산할 수 있다. 이 값은 프로그램의 순수한 순차 코드 비율이라기보다 통신·대기 등까지 반영한 진단 지표다.

e = (1/S(N) − 1/N) / (1 − 1/N)

찾아볼 용어: Karp–Flatt metric.

각주는 추가 탐색을 위한 길잡이다. 실제 시스템에는 여러 병목이 동시에 나타나므로 위 개념들을 측정 결과와 함께 적용한다.
